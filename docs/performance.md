# 生成性能实测

> 2026-11-19 测得。环境：RTX 5060 Laptop 8GB / 16GB RAM / Krea 2 int8 12.6GB /
> `--lowvram --cache-ram 2 --preview-method auto --fast --enable-triton-backend`

## 一、实测数据

| 场景 | 耗时 |
|---|---|
| 1024×1536 · 8 步（冷启动，模型刚加载） | **58.3 s** |
| 1024×1536 · 8 步（第二次） | 48.3 s |
| 1024×1536 · 8 步（第三次） | **42.2 s** |
| 同上但**换提示词** | **60.9 s** |
| 1024×1536 · 16 步 | 88.6 s |
| 512×512 · 8 步 | 26.1 s |

## 二、拆解

**单步 ≈ 5.8 s**（1024×1536）。8 步合计约 46 s，正好是热启的 42 s 主体。

```
总时间 = 模型/编码器加载 + 采样(步数 × 单步) + VAE 解码 + 落盘
         ↑ 首次或换提示词时明显        ↑ 占大头        ↑ 大图 3-6 s
```

**换提示词要多付约 19 s**（60.9 vs 42.2）。这不是重算采样，而是 Qwen3-VL 4B
文本编码器（4.9GB）重新参与编码：权重被挤出 RAM 后要重新搬进来。

**单步耗时随面积增长很慢**：

| 尺寸 | 百万像素 | 单步耗时 |
|---|---|---|
| 512×512 | 0.26 | ≈ 4.0 s |
| 1024×1536 | 1.57 | ≈ 5.8 s |

面积差 6 倍，单步只差 1.45 倍 —— 所以"降分辨率省时间"的效果远不如"降步数"。

## 三、据此做的调整

`run_comfy.bat`：`--cache-ram 2` → **`--cache-ram 6`**

理由：冷热差 16 s，来源就是编码器在 RAM 里待不住。留 6GB 余量让它常驻，
换提示词时不必重新搬 4.9GB。

**回退条件**：如果切到 MOSS（TE 约 7GB）出现明显卡顿或系统内存吃满，
改回 `--cache-ram 2`。注释里写了这一点。

## 四、没做的事（试过或评估过）

| 方案 | 为什么没做 |
|---|---|
| 提高步数换质量 | 5.8s/步，16 步要 88s；8GB 卡上不划算 |
| `--preview-method none` | 省 2–4 s，但会失去步骤预览，不值 |
| `batch_size` 批量出图 | 桥接层按 `n_iter` 串行执行，改批量要动图结构；8GB 上大图批量易 OOM |
| 关闭 `--fast` | 首帧编译 2–5 分钟，长期收益明显，不该关 |

**2026-11-20 更新**：`--fp16-vae` 与 `--cpu-vae` 仍不默认开，但改成了可选项——
见下方第五节与 `install.md` 的显存档位表。

## 四之二、分块 VAE：做了，而且不止省显存（2026-11-20）

原来所有工作流都用整图 `VAEDecode` / `VAEEncode`。改成 `VAEDecodeTiled` /
`VAEEncodeTiled`（`_apply_tiled_vae()` 在组装完成后统一替换，
不在 10 处 build_graph 分支各写一遍）。

`tile_size=512 overlap=64`，可用 `KLOCK_TILED_VAE_TILE` / `KLOCK_TILED_VAE_OVERLAP`
覆盖，`KLOCK_TILED_VAE=0` 整体关闭。

**实测（anima-aesthetic 10 步 1024×1536，各跑 3 次取中位）**：

| 解码方式 | 耗时 | 显存 |
|---|---|---|
| 分块 512/64 | **12.1 s** | 峰值 ≈ tile 级 |
| 整图 | 24.3 s | 峰值 1–2 GB |

**分块更快，不是更慢。** 原因是 8GB 卡上整图解码会触发显存不足 → 反复
offload/swap，这部分开销比分块的额外 kernel 启动大得多。

画质差异：同一 seed 两种解码，平均像素差 **0.19/255**，肉眼无差别，
无接缝、无条带（`_fragmentation_score` 未触发）。

**结论：默认开启**。真要回退：`set KLOCK_TILED_VAE=0`。

### 分块超分：引擎已经做了

`ImageUpscaleWithModel` 内部就是 `comfy.utils.tiled_scale(tile=512, overlap=32)`，
并且 OOM 时会自动 `tile //= 2` 重试到 128。所以 KlockUI 侧没有可传的分块参数，
`UPSCALE_MAX_EDGE = 8192` 限制的是**输出尺寸/落盘体积**，不是分块粒度。

### 分块编码也一并做了

Hires 二采的 `VAEEncode` 同样换成 `VAEEncodeTiled` —— 二采的图比首采大，
编码阶段的显存峰值更需要压。

## 五、给调参的启示

1. **降步数最有效**：8 → 6 步省约 12 s；16 步则要多付 46 s。
2. **分辨率别乱改**：1024×1536 → 832×1216 只省约 25%，但 Krea 2 低于 1K 画质掉得厉害。
3. **同一提示词连跑**几乎不额外收编码器成本，适合固定提示词抽卡。
4. **换模型后第一张最贵**（要重载权重），批量生成时别中途切模型。
5. **别关分块 VAE**：8GB 上它比整图快一倍，还更省显存。
